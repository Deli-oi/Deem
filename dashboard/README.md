# Greenhouse AI: greenhouse dashboard

A standalone web app that shows how Greenhouse AI **scales from one plant to a whole greenhouse**. The greenhouse is a simulation (45 plants, 3 zones), with one exception: the plant tagged **LIVE** (default `A-1-1`) shows the real pot, fed by the ingest service (Pi relay, then the Tiger database): its real readings, alerts and hourly history. If the service is unreachable or the newest reading is older than 25 minutes, that plant goes back to simulated. Set `VITE_INGEST_URL` (and optionally `VITE_LIVE_PLANT_ID`, `VITE_LIVE_DEVICE_ID`) at build time to turn it on.

Same pixel fonts as the device (Silkscreen + VT323) in a cozy, Stardew-Valley-style look: warm parchment page with tiny wildflowers, a wooden sign for the top bar, paper cards, and a sunny greenhouse with wooden planters, rain barrels, fairy lights, flowers outside and a sleeping cat. The mini display in the pop-up stays dark, like the little gadget it is.

## What it shows

1. **The greenhouse (most of the first screen).** A top-down pixel-art floor plan: three climate zones, three raised beds each, 45 plants across all 12 plant types, an air-quality hub per zone, water tanks, a control desk. Every plant shows its health score; plants that need a person flash red. **Click a plant** to open the same mini display the MVP device uses (health, inputs, history; failure screen with the wilted plant if something is wrong), plus that plant's own **soil quality** (moisture, minerals, soil temperature) and the climate around it. **Click an air hub** for the zone's larger sensors (CO2, dust, temperature, humidity, vents, misting).
2. **Greenhouse health.** Overall health rings, key numbers, the three zones' air readings, **what needs a person**, and a log of what the biosphere controller did on its own.
3. **Health by plant type.** One card per plant type with its average health, soil moisture and minerals. Click one to highlight it on the map and filter the list.
4. **Every plant.** All 45 plants, each with moisture and minerals against that type's healthy range.

## The idea it demonstrates

At greenhouse scale a controller keeps the **climate, air and watering** in range automatically, using larger sensors. So the only problems left for a person are the ones it cannot change: **soil quality** (minerals/nutrients). Each plant still has its own probe so every plant type can be kept in the right soil. This is the `AUTO_CORRECTED` idea from the device's alerts (`src/lib/health.ts`), switched on.

In the simulated greenhouse five plants have a soil mineral problem (too low or too high). Everything else is in range.

## Run it

```bash
cd dashboard
npm install
npm run dev          # http://127.0.0.1:5174
npm test             # unit + interaction tests
npm run build && npm start      # serve the production build on :3000
```

## Deploy (a second Railway service)

This is a separate service from the MVP device demo.

1. In the Railway project, **New Service → GitHub repo → `Deli-oi/Greenhouse-AI`**.
2. In its **Settings → Source**, set **Root Directory** to `dashboard`. (`railway.toml` here builds with `npm run build` and starts with `npm start`.)
3. No variables are needed: the dashboard calls no APIs and uses no secrets.

## Reused from the MVP

The dashboard has to build on its own (Railway root directory = `dashboard`), so the pieces it shares with `demo/` are **copied** into `src/shared/` and `public/sprites/`, and `npm run sync` refreshes them:

- the mini display screens (health, inputs, history, failure), activity rings, sprite component, device CSS
- alert rules, advice sentences, plant thresholds and the 12 plant types' data
- all plant sprites, including the wilted ones

Change those in `demo/`, then run `npm run sync` here. Never edit the copies. The transparent map sprites (`public/map/`) are generated by `scripts/make_map_sprites.py` (needs Pillow).

## Layout

| Path | What |
|------|------|
| `src/data/layout.ts` | Floor plan: zones, beds, where each plant stands |
| `src/data/greenhouse.ts` | Simulated readings (a pure function of the time, so it is repeatable but drifts like a live greenhouse), rollups, controller log |
| `src/lib/health.ts` | Greenhouse health scoring and which readings the controller auto-corrects |
| `src/map/` | The pixel-art map (canvas) and its clickable plants and hubs |
| `src/components/` | Pop-ups, the mini display wrapper, page sections |
| `server/` | Tiny static server for Railway (no API) |

## Not real

All readings, the client name ("Verdant Acres"), the controller activity log and the plant placement are made up to show what a full-greenhouse view could look like.
